### **Название задачи:** Передача ставок депозитов в кол-центры
### **Автор:** Архитектор Банка "Стандарт"
### **Дата:** 2025-12-09

### **Функциональные требования**

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
|1|Оператор внутреннего кол-центра, Система кол-центра, Сервис ставок|Консультация клиента по текущим ставкам депозитов|Оператор внутреннего кол-центра получает звонок от клиента. Система кол-центра запрашивает через REST API у Сервиса ставок актуальные ставки депозитов. Оператор видит ставки на своём экране и консультирует клиента.|
|2|Система партнёрского кол-центра, SFTP-сервер, Сервис интеграции депозитов АБС|Получение файла со ставками для партнёрского кол-центра|Сервис интеграции депозитов формирует файл со ставками (CSV/XML) и размещает его на SFTP-сервере. Система партнёрского кол-центра забирает файл с SFTP по расписанию (например, 1 раз в час). Операторы партнёра консультируют клиентов на основе данных из файла.|
|3|Администратор Депозитов, Бэк-офис АБС, Сервис ставок|Изменение ставки депозита|Администратор изменяет ставку депозита в бэк-офисе АБС. Изменения фиксируются в Oracle БД АБС. Сервис ставок получает уведомление об изменении (через CDC или периодический опрос) и обновляет кэш в Redis. Обновлённые ставки становятся доступны для внутреннего кол-центра через API и для партнёрского кол-центра через файл.|

### **Нефункциональные требования**

|**№**|**Требование**|
| :-: | :- |
|1|**Производительность:** REST API для получения ставок должен отвечать < 500 мс (95-й перцентиль)|
|2|**Производительность:** Формирование файла со ставками для SFTP должно занимать < 5 минут|
|3|**Надёжность:** Доступность REST API для внутреннего кол-центра — 99.9% (24/7)|
|4|**Надёжность:** Файл на SFTP должен обновляться не реже 1 раза в час в рабочее время (09:00-21:00 МСК)|
|5|**Безопасность:** REST API защищён OAuth 2.0/JWT аутентификацией. Доступ только для авторизованных систем кол-центра|
|6|**Безопасность:** SFTP-доступ защищён SSH-ключами. Доступ только для системы партнёрского кол-центра|
|7|**Интеграция:** Сервис ставок должен использовать единый источник данных — Oracle БД АБС (через API интеграции АБС)|
|8|**Формат данных:** Файл для SFTP должен быть в формате CSV с заголовками (название депозита, срок, ставка, минимальная сумма, дата обновления)|

### **Решение**

#### Архитектурное решение

**1. Для внутреннего кол-центра (REST API):**

Используем **Сервис ставок** (Rates Service), который уже разрабатывается в рамках MVP (см. Task 3). Добавляем новый REST API endpoint:
- `GET /api/rates/deposits` — возвращает список текущих ставок депозитов в JSON

**Технологии:**
- .NET Core Web API
- Redis Cache для кэширования ставок (TTL 5 минут)
- OAuth 2.0/JWT для аутентификации запросов от системы кол-центра

**Логика:**
1. Система кол-центра вызывает API Gateway
2. API Gateway маршрутизирует запрос в Сервис ставок
3. Сервис ставок проверяет кэш Redis. Если данных нет или кэш устарел — запрашивает данные у API интеграции АБС
4. Возвращает JSON с актуальными ставками

**2. Для партнёрского кол-центра (SFTP):**

Добавляем компонент **Rates File Exporter** в состав **Сервиса интеграции депозитов АБС**:
- Периодически (по расписанию через Cron/Quartz.NET) формирует CSV-файл со ставками
- Размещает файл на SFTP-сервере в выделенной директории для партнёра
- Использует SSH-ключи для аутентификации на SFTP

**Технологии:**
- .NET Core Background Service (Hosted Service)
- SSH.NET или WinSCP .NET библиотека для работы с SFTP
- SFTP-сервер (OpenSSH/ProFTPD)

**Логика:**
1. Scheduled Job запускается каждый час в рабочее время (09:00-21:00 МСК)
2. Компонент Rates File Exporter запрашивает актуальные ставки через API интеграции АБС
3. Формирует CSV-файл с именем `deposit_rates_YYYYMMDD_HHMM.csv`
4. Передаёт файл на SFTP-сервер через SSH-протокол
5. Система партнёрского кол-центра забирает файл по своему расписанию

### **Альтернативы**

**Альтернатива 1: Прямой доступ к Oracle БД АБС**

Системы кол-центров напрямую читают ставки из Oracle БД АБС через Database Link или ODBC.

**Почему отклонена:**
- Перегружает БД АБС дополнительными запросами (уже есть проблема с производительностью БД)
- Нарушает принцип единой точки входа через API Gateway
- Создаёт прямую зависимость внешних систем от внутренней структуры БД АБС
- Усложняет контроль доступа и аудит

**Альтернатива 2: Email-рассылка файлов для партнёрского кол-центра**

Вместо SFTP отправлять файл со ставками на email операторам партнёра.

**Почему отклонена:**
- Менее безопасный канал передачи данных (email может быть перехвачен)
- Требует ручной работы со стороны партнёра (скачивание вложений из почты)
- Отсутствие автоматизации для системы партнёра
- Email не подходит для частых обновлений (каждый час)

**Альтернатива 3: REST API для обоих кол-центров**

Предоставить REST API и для партнёрского кол-центра.

**Почему отклонена:**
- Система партнёрского кол-центра не поддерживает интеграцию через API (техническое ограничение партнёра)
- Партнёр работает только с файлами (legacy система)
- Потребует доработок на стороне партнёра, что увеличивает сроки и стоимость

### **Недостатки, ограничения, риски**

**Недостатки:**
1. **Две разные интеграции:** Необходимо поддерживать два канала передачи ставок (REST API + SFTP файлы). Увеличивает сложность поддержки.
2. **Задержка данных для партнёра:** Партнёрский кол-центр получает обновления с задержкой до 1 часа, в отличие от внутреннего кол-центра (real-time через API).
3. **Дополнительная инфраструктура:** Требуется развернуть и поддерживать SFTP-сервер.

**Ограничения:**
1. Система партнёрского кол-центра не может работать через API — только файловый обмен.
2. SFTP-сервер должен быть доступен из внешней сети партнёра (требуется настройка firewall, DMZ).
3. Формат CSV для файла — упрощённый, не поддерживает сложные структуры данных (например, историю изменений ставок).

**Риски:**
1. **Риск несогласованности данных:** Если партнёр не заберёт файл вовремя, операторы партнёра могут консультировать клиентов по устаревшим ставкам.
   - *Митигация:* Мониторинг забора файлов партнёром. Алерт, если файл не забран в течение 2 часов.

2. **Риск перегрузки API интеграции АБС:** Частые запросы от Сервиса ставок и Rates File Exporter могут перегрузить API АБС.
   - *Митигация:* Использование Redis Cache с TTL 5 минут. Rates File Exporter запрашивает данные только 1 раз в час.

3. **Риск компрометации SFTP-доступа:** Если SSH-ключи партнёра будут скомпрометированы, возможна утечка данных о ставках.
   - *Митигация:* Ротация SSH-ключей каждые 6 месяцев. Мониторинг доступа к SFTP. Файлы со ставками не содержат конфиденциальных данных клиентов (только публичная информация о продуктах).

4. **Риск недоступности SFTP-сервера:** Если SFTP-сервер упадёт, партнёр не сможет получить обновлённые ставки.
   - *Митигация:* Мониторинг доступности SFTP-сервера (healthcheck каждые 5 минут). SLA 99.5% для SFTP. Резервный экземпляр SFTP-сервера в случае отказа основного.
